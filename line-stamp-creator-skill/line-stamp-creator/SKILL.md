# LINEスタンプクリエイター

## 目的

参考画像1枚と表情・文字の定義から、統一感のあるLINEスタンプ、メイン画像、トークルームタブ画像、申請用ZIPを作る。静止画の通常モードに加え、海外向けの文字なしモードと、動きの大きさを活かしたアニメーションモードに対応する。画像生成は原則としてCodex内の画像生成（Image 2.0 / imagegen）を使い、外部APIキーやOpenAI API用スクリプトを前提にしない。生成時は白フチと背景を明確に分離するため、背景を単色マゼンタ（`#ff00ff`）のクロマキー背景として作る。マゼンタ背景は後工程で透過しやすくするための制作仕様であり、ユーザーが「マゼンタ背景まででよい」と指定した場合は、透過変換せずマゼンタ背景PNGとして納品・確認してよい。資料内の手順は作業仕様として扱い、ユーザーが明示していない生成・外部申請は開始しない。

## 作業フロー

1. **入力確認**
   - 参考画像（`reference.png` / `reference.jpg` / `reference.jpeg`）、`expressions.json`、依存関係を確認する。
   - 参考画像がない場合は、ファイル名と配置場所を伝えて停止する。
   - Codex内の画像生成を使う場合、APIキー確認は不要。ローカル検収・梱包に必要なPillow等の依存関係だけを確認する。

2. **表情セットの承認**
   - `references/expressions.json` または作業フォルダ内の `expressions.json` を読み、番号・表情・文字を一覧で提示する。
   - 変更希望を反映し、ユーザーの承認を得るまで画像生成を実行しない。資料内の「承認は表情セットだけ」という指示は、この承認段階の仕様として扱う。
   - 表情セットは、日常の返事・挨拶・感情補足を優先する。了承、感謝、依頼、労い、喜びなど、送る相手と場面の幅が広い表現を中心にする。
   - ネガティブ表現や特定の行動だけを示す表現は少数にとどめる。ただし、明確なコンセプトがある場合は意図と対象ユーザーを確認して採用する。
   - 文字なし海外向けでは、言語に依存しない表情・ジェスチャー・大きな動きを優先し、絵だけで感情と用途が伝わるかを各案で判定する。文字ありの公式推奨と競合するため、対象地域・用途を確認してモードを選ぶ。
   - アニメーションでは、最終採用数の3倍程度を初期案として出す（24個なら60案を目安）。生成の安定性だけで初期案を間引かず、後段の人手確認で不採用にする。

3. **一括生成**
   - `expressions.json` の番号・キャラクター・表情・文字・共通画風から、Codex内の画像生成（Image 2.0 / imagegen）で1枚ずつ生成する。
   - 生成プロンプトでは、背景を必ず単色マゼンタ（`#ff00ff`）のクロマキー背景に指定する。白背景、チェッカー背景、透明背景、グラデーション、質感付き背景は指定しない。
   - 文字・キャラクター・ステッカー外周には太い白フチを付ける。白フチはマゼンタ背景と接しても切り抜きで欠けないよう、連続した太めの輪郭として指定する。
   - 生成前に、参照画像の権利、実在人物・第三者キャラクターの利用許可、画像生成利用の了承を確認する。
   - 生成物は `output/raw/stamp_01.png` のように番号付きで保存する。メイン画像（240×240px想定）とトークルームタブ画像（96×74px想定）も、スタンプ本体と同じ背景仕様・白フチ仕様で必ず同時に作成する。
   - 各スタンプは1つの主感情・主メッセージに絞る。感情を表す顔・手・姿勢などのパーツは大きく、スマホのトーク画面で一目で読める構図にする。
   - 文字入りを基本とし、文字は短く、太く、大きく、背景に埋もれないアウトライン付きにする。文字なしを採用する場合は、絵だけで使いどころと感情が明確かを説明できること。
   - 生成直後の画像にマゼンタ背景が含まれる場合でも、ユーザーが「マゼンタ背景まででよい」と指定しているときは、そこで止めて `output/raw_magenta/` や `output/submit_magenta/` などに整理する。透過変換・ZIP化は明示依頼がある場合だけ行う。
   - 申請用の透過PNGまで進める依頼の場合のみ、マゼンタ領域を透明化したRGBA PNGへ変換する。やり直しは該当番号だけ再生成する。
   - 同梱の `scripts/generate_stamps.py` は外部API用の旧補助スクリプトとして扱い、ユーザーが明示的にAPI利用を希望した場合のみ使う。

### アニメーションモード

   - 参考画像からキャラクターシートを先に作り、見た目・配色・輪郭・表情の基準を固定する。
   - 動きの候補を多数作り、1動作あたり約1.5秒を目安に動画候補へまとめる。動画生成サービスは固定せず、利用可能なツールをユーザーと確認する。
   - 文字なしを基本とし、動きを大きく、単純に、1スタンプ1感情で設計する。グリーンバック／マゼンタ背景などのクロマキーは制作工程の選択肢であり、納品物には背景を残さない。
   - 動画からAPNG化した後、候補を一覧で再生できる確認ページまたはコンタクトシートを作り、人手で24個などの採用数を選定する。
   - 1フレーム目は静止画として表示されるため、動きの途中ではなく、感情と用途が最初から伝わる代表ポーズにする。

4. **検収**
   - `python3 scripts/finalize_stamps.py --check-only` を実行する。
   - 全画像についてRGBA、十分な透明領域、被写体の縁切れなしを確認する。NGは番号指定で最大2回まで再生成し、それでも解消しない場合は利用者へ報告する。
   - 画像を目視できる場合は、文字の誤字、キャラクターの一貫性、白フチ、見切れも確認する。機械検査だけで完成とは言わない。
   - 有効性の目視チェックとして、(a) 1秒以内に主感情が伝わる、(b) 主役の表情・動きが小さくない、(c) 文字が縮小表示でも読める、(d) 送る相手や日常場面が想像できる、を全枚数で確認する。
   - 透過PNGまで進めた場合は、マゼンタ背景が残っていないかを、明色・暗色・青系など複数背景に合成したQC画像で確認する。白フチの内側や文字周辺にマゼンタの縁取り、背景残り、色かぶりが見える場合は、透過処理をやり直す。
   - マゼンタ背景までで止める場合は、背景が単色マゼンタであること、白背景・チェッカー背景・グラデーションが混ざっていないこと、メイン画像とトークルームタブ画像も同じ仕様で存在することを確認する。

5. **規格化・梱包**
   - 検収が通った後だけ `python3 scripts/finalize_stamps.py` を実行する。
   - 申請用の透過PNGまで進める場合、スタンプは370×320px以内、メイン240×240px、トークルームタブ96×74px、各PNG 1MB以下、透過PNGとする。マゼンタ背景までで止める場合も、同じ寸法にそろえて後工程へ渡しやすくする。
   - `output/submit/` と `output/stamps_submit.zip` の存在、ファイル数、サイズを確認する。
   - アニメーションの仕様は、作業開始時に公式ガイドラインを再確認して確定する。現在確認できる公式仕様では、アニメーションスタンプは8/16/24個、最大320×270px、5〜20フレーム、最大再生時間4秒、1ファイル1MB以下、ZIP 60MB以下、APNGのカラーモードRGBである。ユーザー提供文の「300KB以下」など、公式現行値と異なる記述は申請条件として採用しない。

## 完了報告

生成物の絶対パス、検収結果、再生成が必要な番号、申請時の注意を簡潔に報告する。LINE Creators Marketへのアップロードは、ユーザーが明示的に依頼しない限り行わない。APIキー、個人情報、参照画像をGitやチャットへ貼り付けない。

## 同梱リソース

- [expressions.json](references/expressions.json): 初期の8表情・文字と共通画風。

- [finalize_stamps.py](scripts/finalize_stamps.py): 検収、リサイズ、梱包を行う。
- [motion-overseas-guidelines.md](references/motion-overseas-guidelines.md): 文字なし海外向け・動くスタンプの企画、候補選定、APNG検収条件。
